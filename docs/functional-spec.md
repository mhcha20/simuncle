# eSIM 叔叔（SIM uncle）網站功能規格

> 文件用途：概述目前 `simuncle.com` 電商平台的前台、會員、付款、eSIM 履約、供應商整合、內容／SEO、通知、自動化及管理後台功能。
>
> 文件基準：按目前專案程式碼、資料庫 Schema 及功能待辦整理。若某項功能標示為「待完成」，代表已有端點或方案但尚未完成正式排程／進階實作，不能視為已全面上線。

## 1. 系統定位

eSIM 叔叔是一個多語言 eSIM 零售平台，讓客戶按目的地搜尋及購買全球 eSIM 數據方案，付款後由供應商自動建立 eSIM，並透過電郵、訂單頁面及 QR Code 交付。

平台目前支援兩個 eSIM 供應商：

- **Vizlync**：產品同步、下單、eSIM 詳情、用量查詢及增購數據。
- **TGT Technology Global**：產品同步、下單、訂單狀態／Profile 狀態、用量查詢、到期狀態、增值支援及 Callback。

網站同時具備內容營銷及 SEO 系統，包括多語言文章、目的地落地頁、SEO 審查、關鍵字排名、Soro 內容同步及自動化文章／機會關鍵字流程。

## 2. 使用者角色及權限

### 2.1 訪客

訪客不需要註冊即可：

- 瀏覽首頁、產品列表、產品詳情、目的地頁面、安裝教學及部落格。
- 使用地區、國家、數據量、有效期、日費方案及關鍵字搜尋。
- 將產品加入購物車（登入後保存購物車）。
- 使用「立即購買」直接進入 Stripe Checkout。
- 以 Stripe 收集電郵的方式完成訪客結帳。
- 付款後透過電郵及「查詢訂單」功能取得 eSIM。
- 訂閱瀏覽器推播通知。
- 使用 AI 客服及 WhatsApp 客服。

### 2.2 已登入會員

會員可額外使用：

- 個人購物車及購物車數量管理。
- 我的訂單及訂單狀態篩選。
- QR Code、LPA 字串、ICCID、Activation Code 查看及複製。
- eSIM 即時用量及到期日查詢。
- 增購數據／Top-up。
- 終止方案或提前啟用相關操作（視乎供應商及方案支援）。
- 再次購買相同方案。
- 站內通知及瀏覽器推播。
- 推薦碼、推薦連結、佣金及推薦紀錄。

### 2.3 管理員

管理員使用 `/admin` 後台，能管理產品、訂單、內容、通知、價格、匯率、SEO、推薦佣金及系統設定。後端使用 `adminProcedure` 進行權限保護，會員資料及個人訂單使用 `protectedProcedure`。

## 3. 多語言及貨幣

### 3.1 支援語言

全站支援以下六種語言：

- 繁體中文：`zh-TW`
- 簡體中文：`zh-CN`
- English：`en`
- 日本語：`ja`
- 한국어：`ko`
- ไทย：`th`

多語言範圍包括導航、產品列表、產品詳情、訂單狀態、安裝教學、部落格、SEO Meta、電郵、AI 客服、推播及錯誤提示。

產品描述及使用說明會以資料庫欄位保存各語言 AI 翻譯版本；未有翻譯時可按需觸發翻譯並快取結果，減少重複翻譯。

### 3.2 貨幣

- 前台支援貨幣切換及本地化價格顯示。
- 平台主要以 **港幣 HKD** 結算及向 Stripe 收款。
- 後台可管理美元至港幣匯率及其他匯率。
- 非 HKD 顯示時，購物車及產品頁會同時顯示約略 HKD 結算金額。
- 匯率具備最後更新時間，並可由管理員手動更新或透過排程更新。

## 4.7 Stripe 結帳及結果 `/checkout/result`

### 結帳流程

1. 使用者由產品頁或購物車建立 Checkout Session。
2. 後端按產品 ID 從資料庫重新讀取方案及價格。
3. 套用零售加成、匯率、推薦折扣及其他合資格折扣。
4. 以 HKD 及整數 cents 建立 Stripe Checkout。
5. Stripe 收集付款資料；訪客同時收集電郵。
6. 付款成功後由 Webhook 及成功頁補單機制共同處理。
7. 後端向對應供應商建立 eSIM 訂單。
8. 取得 eSIM QR／LPA／ICCID 等資料後更新平台訂單。
9. 發送付款確認電郵及通知。

### 可靠性機制

- Stripe Webhook 簽章驗證。
- 付款成功頁即時確認及補單。
- 對帳排程掃描長時間待付款訂單，向 Stripe 查詢並補回漏接 Webhook 的訂單。
- 具備冪等處理，避免重複建立供應商訂單。
- 付款失敗、供應商失敗及處理錯誤會保留 error message。

### 訪客訂單查詢

- 付款成功後提示確認電郵已發送。
- 電郵包含訂單號碼及 `/track-order` 連結。
- 訪客可使用電郵 + 訂單號碼查詢訂單，不需要建立帳戶。

- 狀態篩選：全部、待付款、未使用／未完成、使用中、已完成、失敗、已失效。

- 可按 URL status 參數保留目前篩選。

### 待付款訂單

- 繼續付款。
- 批量選擇多張待付款訂單。
- 批量建立 Stripe Checkout。
- 清除／標記失敗的待付款訂單。
- 付款提醒由排程自動發送，最多按設定次數提醒。

### eSIM 詳情 Dialog

- QR Code 顯示。
- LPA 字串顯示及複製。
- ICCID 及 Activation Code 顯示及複製。
- iPhone 一鍵安裝 eSIM Universal Link。
- 分享 eSIM／LPA：Web Share API，沒有支援時使用剪貼簿 fallback。
- 顯示啟用方式及有效期計算提示。
- 顯示供應商狀態及最近更新時間。

### 用量及增購數據

- 顯示總數據、已用數據、剩餘數據及進度條。
- 支援 Active、Expired、Not Available、Terminated 等狀態。
- 手動重新整理用量。
- 用量低於 20% 時顯示增購提示並可推播提醒。
- 支援的方案顯示「增購數據」按鈕。
- 精選低／中／高及長有效期增購方案，最多顯示四個主要選項。
- 顯示增購數據量及額外有效期；清楚說明增購有效期不一定延長原主卡到期日。
- 增購付款透過 Stripe，成功後由供應商建立增購訂單。
- 用量會合併母訂單及已完成的增購訂單。
- 沒有增購方案時，按國家及數據量推薦相似產品。

### 方案終止／提前啟用

- 會員可按供應商及方案支援終止方案或提前啟用相關方案。
- 執行前顯示確認 Dialog。
- 若主卡終止但仍有可用增購數據，會提示增購方案可繼續使用。
- 終止後自動更新訂單及用量快取。

- 若供應商資料尚未完整，會即時補取並保存。

# 5. 後台管理功能

- USD／HKD 及其他貨幣匯率。
- 匯率最後更新時間及手動更新。
- WhatsApp 客服電話。
- 熱門目的地。
- 公告橫幅開關、文字、顏色及連結。
- 推播通知發送入口。
- 訂單管理入口。
- 產品管理入口。
- 文章管理入口。
- SEO 儀表板入口。
- 推薦管理入口。
- 產品同步歷史及最近同步狀態。
- 待付款訂單統計及提醒次數。

## 5.2 產品管理 `/admin/products`

### Vizlync 同步

- 從 Vizlync API 取得全球產品。
- 批量 Upsert 至 products_cache。
- 保存產品名稱、描述、價格、有效期、國家、地區、數據量、速度、網絡、通話、SMS、熱點、Profile、啟用方式等資料。
- 記錄最近同步時間、同步數量及失敗數量。
- 顯示失敗 product ID 及錯誤詳情。

### TGT 同步

- 從 TGT API 取得產品並標準化欄位。
- 從產品名稱解析缺失的 dataAmount、每日數據及限速資訊。
- 同步完成後停用 API 已下架而本地仍存在的產品。
- 顯示本次同步新增／更新／停用／失敗／名稱解析數量。

### 產品狀態及內容

- 分頁及搜尋所有產品。
- 啟用／停用產品。
- 修改產品自訂名稱。
- 修改產品自訂描述。
- 批量更新自訂產品欄位。
- 匯出 CSV。
- 查看供應商及原始產品資料。

### 翻譯管理

- 查看每個產品的翻譯狀態。
- 批量觸發繁中、簡中、日文、韓文及泰文翻譯。
- 產品翻譯預覽／編輯 Dialog。
- 以五個語言 Tabs 編輯 description 及 planInfo。
- 以英文原文作參考。
- 單一產品重新翻譯。
- 顯示翻譯統計及完成進度。

## 5.3 訂單管理 `/admin/orders`

### 訂單列表

- 以電郵、產品名稱、訂單號碼等條件搜尋。
- 按付款／履約狀態篩選。
- 分頁顯示訂單。
- 顯示會員／訪客電郵、方案、金額、建立時間、供應商、Supplier Order ID。
- 顯示 Stripe 狀態及訂單狀態。
- 顯示 eSIM 是否已取得。
- 顯示確認電郵是否已發送。
- 顯示付款提醒次數，例如 `N/4`。
- 顯示 TGT Profile 狀態及到期日。
- 顯示錯誤原因。

### 管理員操作

- 查看訂單詳情。
- 預覽 QR Code、LPA、ICCID、Activation Code。
- 一鍵複製 eSIM 資料。

# 9. 電郵、通知及客服流程

## 9.1 付款確認電郵

付款及供應商下單成功後，寄送多語言確認電郵，內容包括：

- 訂單號碼。
- 產品名稱及購買資料。
- QR Code 圖片。
- LPA 字串及安裝說明。
- 訂單查詢連結。
- 供應商資料仍處理中時顯示處理中提示，後端會重試補取。

## 9.2 付款提醒

- 對長時間未付款訂單定期提醒。
- 電郵及推播均可包含「繼續付款」按鈕。
- 使用訂單欄位記錄上次提醒時間及提醒次數。
- 具備去重機制，避免重複大量發送。

## 9.3 到期及用量提醒

- eSIM 接近到期時發送提醒。
- 用量低於 20% 時推送增購或重新購買提示。
- 會員可由通知連結直接回到訂單或產品頁。

## 9.4 管理員客服

- 管理員可從訂單直接發送自訂電郵。
- 可查看每張訂單完整電郵歷史。
- WhatsApp 按鈕直接開啟客戶聯絡。
- 系統通知管理員新訂單、同步失敗及供應商錯誤。

# 10. 安全、可靠性及 UX 要求

- 管理員路由及管理員 tRPC procedures 必須受角色權限保護。
- 會員只能查看自己的訂單及購物車。
- 訪客查詢訂單必須同時驗證訂單號碼及電郵。
- 付款金額、加成、折扣及增購價格由後端重新計算，不信任前端傳入金額。
- Stripe Webhook 需要簽章驗證。
- Webhook、成功頁補單及排程對帳均需保持冪等。
- 供應商密鑰只放在伺服器端，不暴露於前端。
- eSIM 及付款資料不應寫入公開 URL 或前端 Bundle。
- 所有主要操作提供 Loading、錯誤、空資料及成功提示。
- 支援手機版及 iOS Safari／PWA，結帳流程避免大型 Request Body 及被瀏覽器攔截的非同步 Popup。
- 產品圖片、Hero Banner 及安裝圖片使用儲存服務及快取，不直接把大型媒體放進前端 Bundle。
- 重要付款、供應商及通知事件寫入資料庫或系統 Log，方便重試及審核。

# 11. 目前已知待完成／需確認項目

以下項目不應在對外產品介紹中寫成「已完全自動化」：

1. **每月流量報告的 Heartbeat 排程**：報告 API Endpoint、Umami／DB 數據及電郵內容已完成，但每月 1 日 HKT 09:00 的正式排程仍需註冊及驗證。
2. **TGT 進階 API 功能**：包括更完整的 Renewal 與 Data Add-on 區分、Top-up 歷史時間軸、ICCID／IMSI 技術資料折疊區、Callback 事件日誌、同步失敗重試面板、錯誤碼人話化及 Token 健康檢查，部分仍屬規劃或待評估。
3. **TGT 每日同步時間**：如要保證每日指定 HKT 時間執行，需確認對應 Heartbeat／Manus task 已在正式部署環境登記並成功回傳 200。
4. **電郵及第三方服務**：正式環境需持續確認 Resend、Stripe、Vizlync、TGT、Umami、SE Ranking、Soro 等 API Secret、網域及服務權限有效。
5. **多語言內容品質**：系統已支援六語言及 AI 翻譯快取，但部分供應商原始文字、電郵或新文章仍可能需要人工校對。
